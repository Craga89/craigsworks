ai development adoption

Bring AI into the team, keep the quality

AI coding and review introduced the way I did it at Hive: standards written down where people and models can both read them, a pilot on real work, and review that points people at the risky changes rather than replacing them.

signs it would help

Is this you?

If a few of these ring true, it's probably worth a conversation.

  • Some of the team use AI every day, others not at all
  • There's no agreed standard for AI-written code
  • Reviewers can't keep up with the volume of pull requests
  • There are worries about security, privacy or where code goes
  • A tool produced plausible code that didn't fit your codebase
  • Leadership is asking what the plan for AI is

working together

What we would do together

  1. Write the rules down

    Coding and style guidelines in the repo, so the models and the team work to the same standard.

  2. Pilot on real work

    One team, real tickets, a few weeks. We measure what changes rather than guessing.

  3. AI review first, people decide

    Every pull request rated for risk before a person opens it, so attention goes where it matters.

  4. Spread what works

    Turn the routine chores into commands anyone (or any agent) can run, and update onboarding to match.

what i've done before

From AI-assisted to AI-first, in a year

Over the last twelve months I've led Hive's engineering department from first introducing AI-assisted development to the point where the vast majority of code is generated by AI and reviewed by AI alongside people.

how a change gets made now

  1. task
  2. AI generates the code
  3. in-repo guidelines
  4. AI review + risk rating
  5. human review
  6. merged
  • Standards live in the repo, so the models and the team work to the same rules
  • Claude rates every pull request green, amber or red, so reviewers know where to look first
  • Terraform plans get an AI summary as a GitHub check before anyone approves them
  • Chores like cost audits, dataset restores and stacked pull requests are one command, through 20+ Claude Code skills

being straight about it

What AI won't fix on its own

AI makes good habits faster, and bad ones faster too. That's why we start with the groundwork.

  • Unclear standards become inconsistent code, at volume
  • Thin tests let plausible-looking mistakes through
  • Slow CI turns quick generation into a long wait for feedback

If those need work first, I'll say so, and we can start there.
